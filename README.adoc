= partiduo-docs — Décisions et pilotage de Partiduo
:icons: font

*Partiduo* est le portage en Crystal de NOALYSS (https://noalyss.eu), logiciel de
comptabilité libre de Dany De Bontridder. Ce n'est pas un projet officiel NOALYSS.

Dépôt transverse du groupe `prod-crystal/partiduo/` : il porte les décisions
d'architecture (ADR), l'analyse de l'existant et les prompts de lancement qui
valent pour *tous* les projets du groupe.

== Organisation des dépôts

Le groupe Crystal est le miroir du groupe amont https://gitlab.com/noalyss :
chaque projet PHP porté a son équivalent Crystal.

[cols="2,2,3",options="header"]
|===
|Amont — `prod-github/noalyss/` (lecture seule) |Crystal — `prod-crystal/partiduo/` |Remarque

|`noalyss-app` (gitlab `noalyss/noalyss`) |`partiduo-app` |Socle et modules activables (Comptabilité, Facturation…), sans interface
|— |`partiduo-admin` |Administration du parc : cabinets, dossiers, sauvegardes, mises à jour, supervision — voir ADR-008
|— |`partiduo-ui-bulma` |Interface HTMX + Bulma, interchangeable — voir ADR-005
|`peppol-connect` |`partiduo-einvoicing` |Facturation électronique : connecteur de PA abstrait, adaptateurs XP Z12-013 et NOALYSS-PEPPOL — voir ADR-004
|— |`partiduo-teledec` |Télédéclaration (liasse, TVA, DAS2, IS, greffe) par l'API de TELEDEC — voir ADR-007
|— |`partiduo-urssaf` |Tierce déclaration URSSAF des micro-entrepreneurs — voir ADR-007 D7
|— |`partiduo-choruspro` |Factures aux clients publics par Chorus Pro — voir ADR-004 D9
|— |`partiduo-esalink` |Adaptateur de la plateforme agréée EsaLink (Hubtimize), sur la base de l'API XP Z12-013 — voir ADR-004 D2
|— |`partiduo-superpdp` |Adaptateur de la plateforme agréée SuperPDP pour `partiduo-einvoicing` — voir ADR-004 D8
|`noalyss-plugins` |découpé — voir ADR-003 |15 extensions
|`noalyss_xmlpayment` |`partiduo-sepa` |Virements SEPA
|`advancedimport` |`partiduo-import` |Import avancé
|`noalyss_document` |`partiduo-document` |Justificatifs (photos, fichiers, factures reçues) ; dépendance d'`einvoicing`
|`noalyss-form` |`partiduo-form` |Saisie de fiches depuis d'autres sites
|`noalyss-export` |intégré au lot 3 du cœur |Export CSV / FEC
|`profile-management` |absorbé par ADR-002 |Profils et droits
|`copy_parameter` |absorbé par `partiduo-provision` |Sans objet avec une instance par dossier
|— |`partiduo-migrate` |Outil séparé : reprise d'un dossier depuis un FEC ou une base NOALYSS
|`noalyss-documentation` |— |Référence, non portée
|`dolibarr-noalyss` |— |Écarté, non cloné
|===

Tous les dépôts sont hébergés dans l'organisation GitHub `aloli-crystal`, et leur
nom commence par `partiduo-`. Chaque dépôt Crystal a deux branches longues : `development` (intégration) et
`production` (déployée). Pour suivre l'amont : `git -C prod-github/noalyss/<projet> pull`.

== Contenu

* `CARTOGRAPHIE-NOALYSS.adoc` — analyse du cœur PHP.
* `adr/ADR-001-portage-noalyss-crystal.adoc` — choix structurants du portage.
* `adr/ADR-002-authentification.adoc` — authentification, MFA, rôle comptable.
* `adr/ADR-003-contrat-extensions.adoc` — comment une extension se branche sur le cœur.
* `adr/ADR-004-facturation-electronique.adoc` — conformité à la réforme française.
* `adr/ADR-005-interface.adoc` — interface séparée et interchangeable, ergonomie.
* `adr/ADR-006-modules-et-facturation.adoc` — modules activables (comptabilité, facturation…) et facturation conforme.
* `adr/ADR-007-micro-entreprise-et-teledeclaration.adoc` — modules micro-entreprise et professions libérales (2035), télédéclaration par TELEDEC.
* `adr/ADR-008-administration-du-parc.adoc` — application `partiduo-admin` et exécutant des tâches du parc.
* `maquette/` — maquette de référence de l'interface (ADR-005 D6).
* `PROMPT-PORTAGE.adoc` — prompt de lancement du portage du cœur.
* `LIVRABLE.adoc` — livrable du portage : ce qui est fait, comment le lancer, ce qui reste.
